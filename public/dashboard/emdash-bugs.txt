## 1. Standalone Node image transforms need an explicit Sharp dependency
- Observed: November9 initial built store returned HTTP500 for transformed images; declaring Sharp at the application root restored HTTP200. Current resolved Sharp is0.34.5; the exact original pre-fix dependency resolution was not retained.
- Reproduce: build the standalone Node store without application-root Sharp, request a rendered /_image transform, then compare with Sharp installed. Historical reproduction is documented, not freshly rerun against a broken serving release.
- Root cause: required runtime image-transform dependency was absent at the application root. Whether this is an EmDash packaging defect or deployment documentation gap remains unqualified.
- Workaround: keep explicit Sharp in the store package. Evidence: workspace evidence/2026-11-09-cycle.md; template-store package.json. No public outage recreation.

## 3. Concurrent workerd runners collide on the default port
- Versions: live EmDash1.4.0 / sandbox-workerd0.9.6; sender fixture resolves the paired runner from its pinned dependency tree. Node24.22.2.
- Reproduce: start another WorkerdSandboxRunner while live workerd already occupies127.0.0.1:18788 in the same network namespace. The fixture failed binding that address.
- Root cause: each runner instance initializes its first plugin port to18788; no automatic cross-process allocation was observed.
- Workaround: disposable test in a separate network namespace, with explicit cleanup. No live port/service changes. This fixture collision does NOT diagnose item2, already reproduced in isolation.
- Evidence: workspace evidence/2026-11-10-ship-sender-cycle.md; installed sandbox-workerd runner source. Human review should confirm whether a supported port-selection API exists before filing.
