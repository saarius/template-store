## 7. Block Kit form refusal hides its retained Shipping fields
- Versions: signed Commerce0.8.0, serving EmDash1.4.0 (`10beb8c5a`), installed @emdash-cms/blocks1.4.0, Node24.22.2, Playwright1.61.1 Chromium.
- Reproduce: native tee product → Dinkus Commerce → Shipping; enter an invalid M weight with valid L/XL weights, then Save weight. The error is visible but Shipping closes. Reopen Shipping: all three typed values remain, and the invalid submission changed no catalog data. Correct the value and save normally; reload confirms all weights. This is a rendering/continuation sharp edge, not lost input or a failed atomic save.
- Root-cause evidence: the signed plugin response returns Shipping `default_open:true` with the exact refused values, while the rendered trigger reads `aria-expanded=false`. Installed source-map sections show AccordionBlockComponent initializes local state from `default_open` only once, and BlockRenderer keys blocks by block_id or array index. Commerce emits unkeyed accordions and prepends an error block; those initial-state/identity semantics explain why a returned default is not a controlled open request. Whether the owning repair should stabilize plugin block identities or alter host semantics remains for human review; no CMS defect or required host reset is asserted.
- Follow-up November12: compiled-Commerce replay with the pinned Blocks1.4.0 renderer reproduces collapse on unchanged main0ee0a23 for simple/variant products at1440/390px. Stable product/member block_id values prevent validation-banner insertion from transferring card state; Commerce PR267 at2bd422a proposes that focused repair and passes local/CI checks. Review now requests proof through the installed product panel, beyond the isolated renderer mount. This does not establish an EmDash defect or signed deployment.
- Workaround: reopen Shipping before correcting; do not reload until reading the retained input. Save once after correction, then read back the catalog and reload. No signed-plugin replacement, host patch, repeated live save, paid-order edit or forced shipment resync.
- Evidence: evidence/2026-11-12-catalog-weight-native.json (allowlisted signed responses and visible state), catalog-weight-boundaries.json (only the eventual weight save changed data), catalog-weight-renderer-source.json (installed package source map). Native captures remain ignored under template-store runs/backroadbum/catalog-weight/. No EmDash upstream contact.
