# Backroad Bum deployment

Merchant-specific fork branch: `backroadbum/store`. The public store is https://backroadbum.com; this is not a generic TemplateStore release or an upstream change proposal. `PRODUCT.md` and `DESIGN.md` record the provisional brand; the original starter design is archived at `docs/template-design.md`.

## Current state
Five products are stored in EmDash and the pinned Commerce Registry bundle. Road day and Slow camp collections use EmDash descriptions and memberships with the same Commerce listings as the shop. Guest cart, two field notes, HTTPS, protected admin, telemetry and local backups are working. Payments and Ship Registry bundles are mounted. Commerce uses the merchant-only TEST sandbox profile from `saarius/commerce:backroadbum/merchant-profile`, based on the same v0.8.0 pin. A separate default-closed rollout gate permits only an authenticated EmDash Administrator to exercise checkout routes; public paid orders, receipts and sandbox fulfillment remain unverified. A private Node Payments host now runs on loopback 8787 from `saarius/payments:backroadbum/test-runtime`, using v0.5.0's existing ports. An operator-only unpaid $1 TEST session was created, retrieved and immediately expired; this is transport proof, not a store order.

## Operate
- Node 24.22.2, pnpm 11.9.0. Use `NODE_OPTIONS=--max-old-space-size=1200 pnpm exec astro check` on this 2 GB host.
- Store: `backroadbum.service`; proxy: `caddy.service`. Service sources and deploy/backup scripts are in `ops/backroadbum/`.
- Build the merchant Commerce artifact first with `node ops/backroadbum/build.mjs` in its fork. The store deploy stages it at an immutable content-hash path and mounts it through EmDash's Registry sandbox. The service requires `BACKROADBUM_MERCHANT_PROFILE=1`, `BACKROADBUM_CHECKOUT_ENABLED=0`; do not open the gate based on advisory readiness alone.
- Durable data: `/var/lib/backroadbum/content.db` and `uploads/`. Deploys build into `releases/` and atomically switch `current`; two releases and at most three SQLite/upload backups are retained. Snapshots also include a consistent `payments/attempts.db` copy when present; cross-service restoration requires provider reconciliation. Failed or interrupted builds are not promoted and remove their staging directory. Run `bash /var/lib/trialrun/workspace/ops/deploy.sh`.
- `backroadbum-telemetry.timer` samples public-safe health (including private Payments liveness) and host metrics each minute. `backroadbum-backup.timer` takes a daily consistent SQLite/upload snapshot. Backups are local only; off-host recovery remains unfinished.
- Caddy gates private EmDash paths with a random credential; EmDash also requires a passkey. Credentials live only in `/etc/backroadbum/` with mode 0600. The required `/etc/backroadbum/emdash.env` holds the stable plugin-settings encryption key; bootstrap once with `sudo node ops/backroadbum/configure-secrets.mjs` and retain a separate secure recovery copy. Never regenerate it over encrypted settings. The private Caddy configuration is intentionally not committed. Never enable a production dev-bypass.
- `scripts/backroadbum-admin.mjs` opens a local passkey-authenticated browser; always call `saveKey()` and close the browser in `finally` to preserve authenticator counters. Do not run multiple operator helpers concurrently.
- `node scripts/backroadbum-seed.mjs` adopts untouched starter records and creates missing brand products/pages. It deliberately does not reset merchant-edited products or prices.
- `node scripts/verify-backroadbum.mjs` checks public desktop/mobile shopping and refusal boundaries. Evidence goes to ignored `runs/backroadbum/`; no orders or personal data are created.

Own-account Stripe webhooks also need verified provenance and durable wake delivery; see the Payments fork's operator README. Visitor/order aggregates, cycle/token accounting, off-host backups and sandbox shipping remain incomplete; the dashboard reports these as unavailable rather than zero.
