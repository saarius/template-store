# Backroad Bum deployment

Merchant-specific fork branch: `backroadbum/store`. The public store is https://backroadbum.com; this is not a generic TemplateStore release or an upstream change proposal. `PRODUCT.md` and `DESIGN.md` record the provisional brand; the original starter design is archived at `docs/template-design.md`.

## Current state
Five products are stored in EmDash and the pinned Commerce Registry bundle. Road day and Slow camp collections use EmDash descriptions and memberships with the same Commerce listings as the shop. Guest cart, two field notes, HTTPS, protected admin, telemetry and local backups are working. Payments and Ship Registry bundles are mounted. Commerce uses the merchant-only TEST sandbox profile from `saarius/commerce:backroadbum/merchant-profile`, based on the same v0.8.0 pin. A separate default-closed rollout gate blocks every public checkout caller. A private `/api/operator/checkout` adapter requires HTTP authentication plus a current passkey-backed Administrator session and dispatches only canonical guest prepare/start/status through the installed Commerce sandbox; an operator-created paid TEST order is verified. A later loopback-only preview completed the normal guest browser-cart payment, pending recovery and paid receipt flow; Commerce manual fulfillment is now exercised with synthetic tracking; Ship automation remains unconnected. Signed own-account Stripe events now persist immutable wakes in Payments; Commerce's five-minute task reconciled a new TEST order without a shopper return. A private Node Payments host now runs on loopback 8787 from `saarius/payments:backroadbum/test-runtime`, using v0.5.0's existing ports. The earlier unpaid $1 diagnostic remains separate from the later Commerce-backed TEST purchase; both are separate from the browser-cart receipt proof.

## Operate
- Node 24.22.2, pnpm 11.9.0. Use `NODE_OPTIONS=--max-old-space-size=1200 pnpm exec astro check` on this 2 GB host.
- Store: `backroadbum.service`; proxy: `caddy.service`. Service sources and deploy/backup scripts are in `ops/backroadbum/`.
- Build the merchant Commerce artifact first with `node ops/backroadbum/build.mjs` in its fork. The store deploy stages it at an immutable content-hash path and mounts it through EmDash's Registry sandbox. The service requires `BACKROADBUM_MERCHANT_PROFILE=1`, `BACKROADBUM_CHECKOUT_ENABLED=0`; do not open the gate based on advisory readiness alone.
- Durable data: `/var/lib/backroadbum/content.db` and `uploads/`. Deploys build into `releases/` and atomically switch `current`; two releases and at most three SQLite/upload backups are retained. Snapshots also include a consistent `payments/attempts.db` copy when present; cross-service restoration requires provider reconciliation. Failed or interrupted builds are not promoted and remove their staging directory. Run `bash /var/lib/trialrun/workspace/ops/deploy.sh`.
- `backroadbum-telemetry.timer` samples public-safe health (including private Payments liveness) and host metrics each minute. `backroadbum-backup.timer` takes a daily consistent SQLite/upload snapshot. Backups are local only; off-host recovery remains unfinished.
- Caddy gates private EmDash paths with a random credential; EmDash also requires a passkey. Credentials live only in `/etc/backroadbum/` with mode 0600. The required `/etc/backroadbum/emdash.env` holds the stable plugin-settings encryption key; bootstrap once with `sudo node ops/backroadbum/configure-secrets.mjs` and retain a separate secure recovery copy. Never regenerate it over encrypted settings. The private Caddy configuration is intentionally not committed. Never enable a production dev-bypass.
- `scripts/backroadbum-admin.mjs` opens a local passkey-authenticated browser; always call `saveKey()` and close the browser in `finally` to preserve authenticator counters. Do not run multiple operator helpers concurrently.
- `node scripts/backroadbum-seed.mjs` adopts untouched starter records and creates missing brand products/pages. It deliberately does not reset merchant-edited products or prices.
- `node scripts/backroadbum-checkout-status.mjs --check` reconciles the existing private operator proof through Commerce, checks stable paid-order replay and reports only safe facts. It never starts another payment; its capability remains in `/etc/backroadbum/operator-checkout.json`0600.
- `bash ops/backroadbum/checkout-preview.sh start` starts the current release at loopback4322 with checkout enabled only there. It shares the merchant database and uses a private mount-namespace copy of EmDash's runner with only nanoservice ports changed (19788 onward), avoiding the live runner's fixed ports. The proxy and live service are unchanged. Stop it with the same script's `stop` command after checking.
- `node scripts/backroadbum-shopper-status.mjs --check --capture` reopens the existing guest-browser proof from `/etc/backroadbum/shopper-browser.json`0600 in that preview. Use `--state-file=/etc/backroadbum/webhook-shopper-browser.json` for the later background-reconciled order. It verifies paid TEST receipt/reload, settled cart, phone layout and denial to a fresh browser without its capability. Add `--fulfillment=completed` for #1003 or `--fulfillment=processing` when verifying an intentionally reopened order; these only read the current Commerce state. It never creates a new payment; captures stay ignored. The browser helper strips auth cookies and uses normal guest endpoints, not the operator adapter.
- Payments `ops/backroadbum/replay-webhook.mjs --check|--resend` inspects or asks Stripe to redeliver the retained shopper proof's real completed event. Load the private Stripe environment without echoing it; optional `--state-file` selects the later webhook proof. No new session/payment/order is created; signing stays at Stripe. The endpoint is `/v1/webhooks/stripe`; wake list/ACK require exact merchant/site/scope passes. See the Payments operator README for provenance and replay rules.
- `node scripts/verify-backroadbum.mjs` checks public desktop/mobile shopping and refusal boundaries. Evidence goes to ignored `runs/backroadbum/`; no orders or personal data are created.

## Next
Add bounded public checkout admission and replace the telemetry prepare POST with a non-creating readiness probe before public rollout. Commerce manual fulfillment is proven; Ship automation remains a separate connection task, not evidence of carrier movement. Guest-browser receipts and webhook-driven background order reconciliation are privately proven; do not confuse that with an already-public checkout. The generic Commerce trust boundary stays unchanged; only the explicit merchant profile uses this merchant's issuer and exact host. Own-account Stripe signature verification, independent event retrieval and durable wake delivery are now wired; generic Connect behavior is unchanged. Investigate the observed Node image dependency gap on an isolated generic branch before proposing an upstream patch. Visitor/order aggregates, cycle/token accounting, off-host backups and sandbox shipping remain incomplete; the dashboard reports these as unavailable rather than zero.
