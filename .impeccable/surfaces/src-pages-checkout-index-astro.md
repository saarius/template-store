# Checkout and return
Mode: Operate. Primary action: complete a test purchase, then understand and recover its receipt.

Preserve the store's daylight-blue fields and yellow action. Address forms use ordinary labeled controls; the order summary stays beside contact entry on desktop and stacks below it on phones. Put test-card instructions beside the form, not in a modal.

Only Commerce's capability-scoped paid order can confirm. Never trust a Stripe return URL as paid proof; keep pending recovery separate from new checkout. Show the canonical TEST label and explain that recovery requires the same browser's site data. No decorative stamps, imitation barcodes or promises of unconnected email/shipping services. Show Commerce’s current fulfillment separately from paid money. Label TEST tracking as synthetic text with no carrier link; complete is not delivered. Public merchant checkout is open behind durable request limits. A limit is not a payment failure: preserve the cart and explain when to retry. Recovery instructions must not promise unverified email delivery.

Receipt rediscovery extends this surface without adding a new visual world: permanent footer and cart links open the existing return page, never an order identifier or credential in a URL. Name the latest-checkout-only browser limit and distinguish a browser with no saved checkout from an unsuccessful payment. Verify empty, corrupt and blocked storage without minting a capability; paid receipts still require canonical Commerce status.
